# Power BI Report Server (on-premises) REST API v2.0, SOAP and URL-access surface — inventory and data-out capabilities

Scope: on-premises Power BI Report Server (PBIRS) only. Anything that applies only to Power BI Service / Fabric is flagged **[CLOUD ONLY]**. Primary sources used: the official PBIRS 2.0 OpenAPI spec on SwaggerHub (downloaded as JSON from `https://api.swaggerhub.com/apis/microsoft-rs/PBIRS/2.0` and compared programmatically against `https://api.swaggerhub.com/apis/microsoft-rs/SSRS/2.0`), the Microsoft Learn PBIRS REST reference (`https://learn.microsoft.com/en-us/rest/api/power-bi-report/`), Microsoft Learn SSRS URL-access / rendering docs, and the ReportingServicesTools module manifest.

---

## Key Question 1 — Is there ANY REST or SOAP action in PBIRS that executes a DAX query or returns table data from a .pbix embedded model?

### Takeaway
No. The complete PBIRS REST API v2.0 spec (143 paths) contains no action that executes DAX/MDX or returns rows from a .pbix data model; the only data-returning endpoints (`/DataSets({Id})/Model.GetData`, `/DataSets({Id})/Data`, `/DataSets({Id})/Model.GetAggregatedValue`) are defined on the `DataSets` entity, which is the shared paginated-report dataset (.rsd) catalog type, not the PowerBIReport entity. The only `.pbix`-related byte stream is `GET /PowerBIReports({Id})/Content/$value`, which returns the whole file as `application/octet-stream`.

### Cited Findings
- The PBIRS 2.0 swagger info block describes the API as "programmatic access to the report server catalog" and lists its Power BI additions as only: "October 2020 Release: /PowerBIReports({Id})/DataModelParameters (GET & POST); January 2019 Release: /PowerBIReports({Id})/DataModelRoles (GET), /PowerBIReports({Id})/DataModelRoleAssignments (GET & PUT)". — [SwaggerHub PBIRS 2.0 (raw JSON)](https://api.swaggerhub.com/apis/microsoft-rs/PBIRS/2.0)
- Full list of `/PowerBIReports` paths and verbs in the PBIRS 2.0 spec (verified by parsing the JSON): `/PowerBIReports` GET, POST; `/PowerBIReports({Id})` GET, PATCH, DELETE; `/PowerBIReports({Id})/AllowedActions` GET; `/PowerBIReports({Id})/CacheRefreshPlans` GET; `/PowerBIReports({Id})/Comments` GET, POST; `/PowerBIReports({Id})/Comments({CommentId})` PUT, DELETE; `/PowerBIReports({Id})/Content/$value` GET; `/PowerBIReports({Id})/DataModelParameters` GET, POST; `/PowerBIReports({Id})/DataModelRoleAssignments` GET, PUT; `/PowerBIReports({Id})/DataModelRoles` GET; `/PowerBIReports({Id})/DataSources` GET, PATCH; `/PowerBIReports({Id})/Model.CheckDataSourceConnection` POST; `/PowerBIReports({Id})/Model.Upload` POST; `/PowerBIReports({Id})/Policies` GET, PUT; `/PowerBIReports({Id})/Properties` GET, PUT. ### Inferences
- Any connector that needs tabular data out of a .pbix hosted on PBIRS cannot do so through the documented REST or SOAP surface; the only documented options are (a) download the .pbix via `Content/$value` and process it offline, (b) have the model's upstream source (SQL etc., discoverable via `/PowerBIReports({Id})/DataSources` `DataModelDataSource.Kind`) queried directly, or (c) an unsupported local connection to the embedded `msmdsrv.exe` on the server host.
- The "api/reports/{id}/data?rs:Format=CSV" suggestion in the community mixes REST-style and URL-access (`rs:`) syntax and is not in any spec; it should not be relied upon.

### Gaps
- No official Microsoft statement was found that explicitly says "DAX execution is unsupported on PBIRS"; the conclusion rests on the exhaustive absence from the spec plus community confirmations.
- The embedded-engine details (port file path, local-only connectivity) come from one community answer whose page blocked automated fetching; could not be independently verified against official docs.

## Key Question 2 — What does the web portal use when a user clicks "Export data" on a visual in a .pbix report in PBIRS? Is it reusable/documented?

### Takeaway
Microsoft documents only the user-facing behavior (export summarized/underlying data to .xlsx/.csv, with the same 150K-row xlsx limit as the service since the October 2020 release) and the designer/admin controls; no official or reliable community source documents the internal HTTP endpoint the PBIRS portal calls for visual export, and no evidence was found that it is supported or stable for reuse.

### Cited Findings
- PBIRS October 2020 release: "Exporting to Excel from a Power BI report in Power BI Report Server now works the same as exporting to Excel from a Power BI report in the Power BI service. You can export directly to the Excel .xlsx format, and the export limit is 150 K rows." — [Learn: What's new in PBIRS](https://learn.microsoft.com/en-us/power-bi/report-server/whats-new)
- Designer controls (set in Power BI Desktop File > Options > Report settings > Export data) are: "Allow end users to export summarized data from the Power BI service or Power BI Report Server", "Allow end users to export both summarized and underlying data from the service or Report Server", "Don't allow end users to export any data from the service or Report Server". — [Learn: Export data from a Power BI visualization](https://learn.microsoft.com/en-us/power-bi/visuals/power-bi-visualization-export-data)
- Service limits documented on the same page (stated for Desktop/service; PBIRS adopted the "same as service" behavior): .csv up to 30,000 rows; .xlsx up to 150,000 rows; DirectQuery export max 16 MB uncompressed; exported rows are filtered and (for summarized) aggregated; first row lists "Applied filters". — [Learn: Export data from a Power BI visualization](https://learn.microsoft.com/en-us/power-bi/visuals/power-bi-visualization-export-data)
- The PBIRS January 2020 release added "Power BI visuals API" and other items but no export API; the only server-side developer surface added in 2019–2020 was DataModelRoles/RoleAssignments (Jan 2019) and DataModelParameters (Oct 2020). — [Learn: What's new in PBIRS](https://learn.microsoft.com/en-us/power-bi/report-server/whats-new); [SwaggerHub PBIRS 2.0](https://api.swaggerhub.com/apis/microsoft-rs/PBIRS/2.0)
- A third-party tool, `cameronaaron/powerbi-extract`, "Extract tabular data out of Power BI public-report visuals by replaying their querydata calls" — this targets Power BI *public (publish-to-web) reports*, i.e. **[CLOUD ONLY]**, not PBIRS. — [GitHub: powerbi-extract](https://github.com/cameronaaron/powerbi-extract)
- Microsoft Q&A / community answer for the service: "currently, Power BI only support us to export report by rest api instead of export data from specific visualization" **[CLOUD ONLY]**. — [Fabric Community: API to export data from Power BI visuals](https://community.fabric.microsoft.com/t5/Developer/API-to-export-data-from-Power-Bi-Visuals/m-p/4068993/highlight/true)
- Embedded JavaScript SDK `visual.exportData` exports a visual's data to CSV but requires the report to be embedded via the Power BI client SDK (an embedding scenario, not available for PBIRS-hosted reports). — [Learn: Export data from a visual in Power BI embedded analytics](https://learn.microsoft.com/en-us/javascript/api/overview/powerbi/export-data)

### Inferences
- Because PBIRS renders .pbix reports with the same web front-end as the service, the portal almost certainly posts visual queries to an internal, undocumented endpoint under the report server's web portal; nothing in Microsoft docs or the swagger exposes or supports it, so a connector that replayed it would depend on an unversioned private API that changes with each PBIRS release.

### Gaps
- Searches for PBIRS-specific traffic captures ("api/explore", "querydata", "conceptualschema", "/powerbi/api" together with "Report Server") returned no blog posts, Q&A threads, or GitHub projects documenting the on-prem portal's internal endpoints. The exact internal route names for PBIRS could not be confirmed from any source.

## Key Question 3 — Exact semantics and formats of `Datasets({id})/Model.GetData`; does it exist in PBIRS 2.0; what does it return; limits?

### Takeaway
Yes, `POST /DataSets({Id})/Model.GetData` is in both the SSRS 2.0 and PBIRS 2.0 specs and the Learn PBIRS reference; it takes an optional `MaxRows` query parameter and an optional JSON body `{ "Parameters": [ {Name, Value} ] }`, and returns JSON `{ Name, Columns:[{Name,Type}], Rows:[[string,...],...] }`. It operates on shared datasets (.rsd `DataSet` catalog items) only; a sibling OData feed `GET /DataSets({Id})/Data` and a schema call `GET /DataSets({Id})/Model.GetSchema` also exist.

### Cited Findings
- Spec (quoted from the JSON): `/DataSets({Id})/Model.GetData` POST — summary "Gets the query results for the specified DataSet.", operationId `GetDataSetData`; parameters: `MaxRows` (in: query, type number, format Int32, optional, "Specifies the maximum number of rows to return from the query."), body `DataSetDataParameters` = `{ "Parameters": [DataSetParameter] }` where `DataSetParameter` = `{Name: string, Value: string}`; 200 response schema `DataSetData` = `{ "Name": string, "Rows": array of array of string, "Columns": array of {"Name": string, "Type": string} }`; 404 "Not Found." — [SwaggerHub PBIRS 2.0](https://api.swaggerhub.com/apis/microsoft-rs/PBIRS/2.0)
- Learn reference confirms `POST /DataSets({Id})/Model.GetData`, "Gets the query results for the specified DataSet.", request body `MaxRows` (number), responses 200/404/Other. — [Learn: Data Sets - Get Data Set Data](https://learn.microsoft.com/en-us/rest/api/power-bi-report/data-sets/get-data-set-data)
- `GET /DataSets({Id})/Model.GetSchema` — "Gets the schema for the specified DataSet."; 200 returns `DataSetSchema` = `{ Name, Fields: [DataSetField{Name, DataType}], Parameters: [DataSetParameterInfo{Name, DefaultValue, Nullable, DataType, IsExpression, IsMultiValued}] }`; `DataType` enum `ReportParameterType` = Boolean, DateTime, Integer, Float, String. — [SwaggerHub PBIRS 2.0](https://api.swaggerhub.com/apis/microsoft-rs/PBIRS/2.0)
- `GET /DataSets({Id})/Data` (operationId `GetDataSetODataFeed`) — "Gets the data for a given DataSet. With the exception of the ID property, columns that are defined in the DataSet will be returned as open or dynamic types in the result."; 200 returns `{ "@odata.context": string, "value": [DataSetRow] }` where `DataSetRow` declares only `Id` (uuid) plus open-type columns. — [SwaggerHub PBIRS 2.0](https://api.swaggerhub.com/apis/microsoft-rs/PBIRS/2.0); [Learn: Get Data Set O Data Feed](https://learn.microsoft.com/en-us/rest/api/power-bi-report/data-sets/get-data-set-o-data-feed)
- `POST /DataSets({Id})/Model.GetAggregatedValue` — query params `ColumnName` (required) and `Aggregation` (required; values from `KpiSharedDataItemAggregation` = None, First, Last, Min, Max, Average, Sum), optional body `{Parameters:[...]}`; 200 returns array of double. — [SwaggerHub PBIRS 2.0](https://api.swaggerhub.com/apis/microsoft-rs/PBIRS/2.0)
- `DataSet` entity definition: derives from CatalogItem, adds `HasParameters` (bool) and `QueryExecutionTimeOut` (int32 seconds); described as "analogous to a view in a database and can include a data source pointer, a query definition, and optional parameter values" — i.e., the SSRS shared dataset. `CatalogItemType` enum: Unknown, Folder, Report, DataSource, DataSet, Component, Resource, Kpi, MobileReport, LinkedReport, ReportModel, PowerBIReport, ExcelWorkbook. — [SwaggerHub PBIRS 2.0](https://api.swaggerhub.com/apis/microsoft-rs/PBIRS/2.0)
- Chris Webb's blog comment thread: a reader noted "You CAN directly leverage the odata from an SSRS-SharedDataset, no POST request needed" via "/Datasets(GUID)/data" with "include open type columns" enabled in Power BI's OData connector. — [Chris Webb's BI Blog](https://blog.crossjoin.co.uk/2017/10/15/exploring-the-new-ssrs-2017-api-in-power-bi/)
- C# Corner shows reading shared-dataset data via `GET /datasets(<guid>)/data`. — [C# Corner: Accessing REST API in PBIRS](https://www.c-sharpcorner.com/blogs/powerbi-report-server-rest-api)
- Community confirmation that `/DataSets` only lists shared datasets, and users with only .pbix content get an empty array / cannot use Model.GetData for pbix. — [Fabric Community: /DataSets({Id})/Model.GetData](https://community.fabric.microsoft.com/t5/Report-Server/DataSets-Id-Model-GetData/td-p/428660); [Fabric Community](https://community.fabric.microsoft.com/discussions/reportserver/get-sql-server-data-from-power-bi-report-servers-rest-api/4400839)
- Spec-vs-spec note: in the SwaggerHub documents, `/DataSets({Id})/Data` appears only in the PBIRS 2.0 file, not in the SSRS 2.0 file, even though the 2017 blog comment reports it working on SSRS 2017; the SSRS 2.0 SwaggerHub document appears to lag the product. — [SwaggerHub SSRS 2.0](https://api.swaggerhub.com/apis/microsoft-rs/SSRS/2.0); [SwaggerHub PBIRS 2.0](https://api.swaggerhub.com/apis/microsoft-rs/PBIRS/2.0)

### Inferences
- `Model.GetData` returns all values as strings (Rows is `string[][]`), with column types given separately in `Columns[].Type`; a connector must coerce types client-side.
- `MaxRows` is the only documented limit; no server-side default page size for Model.GetData is documented.

### Gaps
- No documentation of the default row cap when `MaxRows` is omitted, of a maximum allowed `MaxRows`, or of how `/DataSets({Id})/Data` pages (`@odata.nextLink`) — none of these are stated in the spec or Learn pages.
- Whether `Model.GetData` honors the dataset's `QueryExecutionTimeOut` or the server's global timeout is not documented.

## Key Question 4 — What does `Reports({id})/Export/{format}` support, and how to render only a dataset's raw data (CSV device info `rc:` params, ReportExecution2005 `Render` with CSV)?

### Takeaway
There is no `Export` action on `/Reports` in the REST API 2.0 at all; export of paginated reports is done via URL access (`/ReportServer?/path&rs:Format=CSV&rc:<setting>=...`) or the SOAP `ReportExecution2005.Render(Format, DeviceInfo, ...)`. The CSV renderer flattens the report's *data regions* (tables, matrices, charts), not the raw dataset rows; the closest "data-only" output is CSV with `rc:ExcelMode=false` (RFC 4180 compliant mode, header once, unformatted values) or the XML renderer. None of these apply to .pbix items.

### Cited Findings
- The PBIRS 2.0 spec's complete `/Reports` surface: `/Reports` GET, POST; `/Reports({Id})` GET, PATCH, DELETE; `/AllowedActions` GET; `/CacheOptions` GET, PUT; `/CacheRefreshPlans` GET; `/Comments` GET, POST; `/Comments({CommentId})` PUT, DELETE; `/Content/$value` GET; `/DataSources` GET, PUT; `/DependentItems` GET; `/HistorySnapshotOptions` GET, PUT; `/HistorySnapshots` GET, POST; `/HistorySnapshots({HistoryId})` GET, DELETE; `/Model.CheckDataSourceConnection` POST; `/Model.UpdateCacheSnapshot` POST; `/Model.UpdateReportDataSets` POST; `/Model.Upload` POST; `/ParameterDefinitions` GET, PATCH; `/Policies` GET, PUT; `/Properties` GET, PUT; `/SharedDataSets` GET, PUT; `/Subscriptions` GET. No `Export`. — [SwaggerHub PBIRS 2.0](https://api.swaggerhub.com/apis/microsoft-rs/PBIRS/2.0); [Learn: Reports operations](https://learn.microsoft.com/en-us/rest/api/power-bi-report/reports)
- URL access: "Specify the format in which to render a report by using the `rs:Format` URL parameter" e.g. `https://myrshost/ReportServer?/myreport&rs:Format=PDF`; common values: HTML4.0, HTML5, MHTML, IMAGE, EXCELOPENXML (xlsx), WORDOPENXML (docx), CSV, PDF, XML, NULL; "If a specified rendering extension isn't installed on the report server, an error displays". — [Learn: Export a report by using the rs:Format URL parameter](https://learn.microsoft.com/en-us/sql/reporting-services/export-a-report-using-url-access)
- URL access parameter reference: `rs:Format` values `HTML5, PPTX, ATOM, HTML4.0, MHTML, IMAGE, EXCEL (.xls), EXCELOPENXML (.xlsx), WORD (.doc), WORDOPENXML (.docx), CSV, PDF, XML`; "For a complete list, see the `<Render>` extension section of the report server rsreportserver.config file". Device info is passed as `rc:tag=value` "where tag is the name of a device information setting specific to the rendering extension" (e.g. `&rs:Format=IMAGE&rc:OutputFormat=JPEG`). Other `rs:` commands: `rs:Command=ListChildren|GetChildren|Render|GetSharedDatasetDefinition|GetDataSourceContents|GetResourceContents|GetComponentDefinition`, `rs:ParameterLanguage`, `rs:Snapshot`, `rs:PersistStreams`, `rs:GetNextStream`, `rs:SessionID`, `rs:ClearSession`, `rs:ResetSession`, `rs:ShowHideToggle`. `rc:` HTML-viewer commands: Toolbar, Parameters, Zoom, Section, FindString, StartFind, EndFind, FallbackPage, GetImage, Icon, Stylesheet. — [Learn: URL access parameter reference](https://learn.microsoft.com/en-us/sql/reporting-services/url-access-parameter-reference)
- `rs:Command=GetSharedDatasetDefinition` "Display[s] the XML definition associated with a shared dataset ... These properties include the query, dataset parameters, default values, dataset filters" and requires Read Report Definition permission; example `https://localhost/reportserver/?/DataSet1&rs:command=GetShareddatasetDefinition`. — [Learn: URL access parameter reference](https://learn.microsoft.com/en-us/sql/reporting-services/url-access-parameter-reference)
- CSV device information settings (all usable as `rc:<Name>=` on a URL or as `<DeviceInfo><Name>..</Name></DeviceInfo>` in SOAP): `Encoding` (default UTF-8), `ExcelMode` (default **true**), `FieldDelimiter` (default `,`; URL-encode, e.g. `%09` for TAB), `FileExtension` (default .CSV), `NoHeader` (default false), `Qualifier` (default `"`), `RecordDelimiter` (default `<cr><lf>`), `SuppressLineBreaks` (default false), `UseFormattedValues` (default true when ExcelMode true, otherwise false). — [Learn: CSV device information settings](https://learn.microsoft.com/en-us/sql/reporting-services/csv-device-information-settings)
- There is **no** `rc:ItemPath` / per-data-region selector documented among the CSV device info settings; the documented list is exactly the nine settings above. — [Learn: CSV device information settings](https://learn.microsoft.com/en-us/sql/reporting-services/csv-device-information-settings)
- CSV renderer semantics: it "renders paginated reports as a flattened representation of data from a report", MIME `text/csv`; page header/footer, lines, images, rectangles and automatic subtotals are ignored; "Table: Renders by expanding the table and creating a row and column for each row and column at the lowest level of detail"; "Each top-level peer data region in the report body is rendered in its own data block" (Default/Excel mode, blocks separated by empty lines); in **Compliant mode** (ExcelMode=false) "Only the first row of the file contains the column headers and each row has the same number of columns" and "Values are unformatted". — [Learn: Export a paginated report to a CSV file](https://learn.microsoft.com/en-us/sql/reporting-services/report-builder/exporting-to-a-csv-file-report-builder-and-ssrs)
- SOAP `ReportExecution2005.asmx` `Render` signature: `byte[] Render(string Format, string DeviceInfo, out string Extension, out string MimeType, out string Encoding, out Warning[] Warnings, out string[] StreamIds)`; "DeviceInfo: An XML string ... settings must be passed as internal elements of a DeviceInfo XML element"; requires prior `LoadReport(reportPath, historyID)` and optional `SetExecutionParameters(parameters, "en-us")` with the `ExecutionHeader` SOAP header; permissions ReadProperties AND ExecuteAndView; "A limitation of the Render method is that the output cannot be streamed, so the entire file must be in-memory". Example endpoint URL: `http://myserver/reportserver/ReportExecution2005.asmx`. — [Learn: ReportExecutionService.Render](https://learn.microsoft.com/en-us/dotnet/api/reportexecution2005.reportexecutionservice.render?view=sqlserver-2016)
- The SOAP management endpoint `ReportService2010.asmx` (class `ReportingService2010`) groups methods into: namespace management, authorization, data sources and connection, report parameters, model, rendering and execution (caching), report history, scheduling (shared schedules and cache refresh plans), subscription and delivery, linked reports. — [Learn: Report Server Web service methods](https://learn.microsoft.com/en-us/sql/reporting-services/report-server-web-service/methods/report-server-web-service-methods)
- The SSRS CSV/URL-access docs apply to paginated (.rdl) reports; the Power BI (.pbix) export path documented for PBIRS is the portal's per-visual export (see KQ2), not `rs:Format`. — [Learn: Export a report by using the rs:Format URL parameter](https://learn.microsoft.com/en-us/sql/reporting-services/export-a-report-using-url-access); [Learn: What's new in PBIRS](https://learn.microsoft.com/en-us/power-bi/report-server/whats-new)

### Inferences
- To get "dataset-like" raw rows from a paginated report via rendering, the practical pattern is: author (or generate) an RDL with a single table bound to the dataset and render with `rs:Format=CSV&rc:ExcelMode=false&rc:UseFormattedValues=false` (one header row, unformatted values). For a pre-existing shared dataset, `POST /DataSets({Id})/Model.GetData` or `GET /DataSets({Id})/Data` is far simpler.
- Since no `rc:` selector exists for a specific data region, multi-region reports exported to CSV must be split client-side (Excel mode) or will be merged with repeated parent columns (compliant mode).

### Gaps
- No official source lists exact `rsreportserver.config` `<Render>` extension names for PBIRS specifically (the docs defer to the config file).
- The `ATOM` renderer (data feeds) is listed in the URL-access parameter table but its device-info/`rc:` parameters were not researched.

## Key Question 5 — Does the REST API expose pbix refresh (CacheRefreshPlans) status/history and Power BI dataset metadata (`DataModelDataSource` kinds)? What fields are in `PowerBIReport`?

### Takeaway
Yes: `GET /PowerBIReports({Id})/CacheRefreshPlans`, `GET /CacheRefreshPlans({Id})` (with `LastRunTime`, `LastStatus`, `Schedule`), `GET /CacheRefreshPlans({Id})/History` (returns `SubscriptionHistory` records with `SubscriptionStatus` = Completed|InProgress|Failed, `StartTime`, `EndTime`, `Message`, `Details`), and `POST /CacheRefreshPlans({Id})/Model.Execute` (204) are all in the PBIRS spec. `PowerBIReport` is just `CatalogItem` + `HasDataSources`; model metadata is exposed via `/DataSources` (with `DataModelDataSource.Kind/AuthType/Type`), `/DataModelParameters`, `/DataModelRoles`, `/DataModelRoleAssignments`.

### Cited Findings

## Key Question 6 — Does PBIRS REST support `$filter`, `$search`, `$top/$skip`, `$orderby`, `$expand`, and what are the OData quirks?

### Takeaway
Collection GETs (`/CatalogItems`, `/PowerBIReports`, `/Reports`, etc.) declare `$top`, `$skip`, `$filter`, `$count`, `$orderBy` (note capital B in the spec), and `$select`; `$expand` is defined as a global parameter but is not attached to the collection operations; `$search` is not in the spec — folder search is a separate action `POST /Folders({Id})/Model.SearchItems(searchText='...')`. Items may be addressed by GUID or by `path='/folder/item'` (single quotes doubled for escaping).

### Cited Findings
- Global parameters in the spec: `$top` ("Show only the first n items"), `$skip` ("Skip the first n items"), `$count` ("Include count of items", type string), `$filter` ("Filter items by property values"), `$orderBy` ("Order items by property values"), `$expand` ("Expand related entities"), `$select` ("Select properties to be returned"), each linking to the OData v4.0 protocol spec. — [SwaggerHub PBIRS 2.0](https://api.swaggerhub.com/apis/microsoft-rs/PBIRS/2.0)
- `GET /PowerBIReports` and `GET /CatalogItems` reference exactly `top, skip, filter, count, orderby, select` (not `expand`); responses are `{ "@odata.context": string, "@odata.count": integer, "value": [...] }`. — [SwaggerHub PBIRS 2.0](https://api.swaggerhub.com/apis/microsoft-rs/PBIRS/2.0)
- No `$search` parameter exists in the spec; `POST /Folders({Id})/Model.SearchItems(searchText='{searchText}')` — "Searches items in a given folder." returns `ODataCatalogItems`. — [SwaggerHub PBIRS 2.0](https://api.swaggerhub.com/apis/microsoft-rs/PBIRS/2.0)
- Key addressing: "The key (GUID or path) that uniquely identifies the object. GUID example: 01234567-89ab-cdef-0123-456789abcdef path example: path='/folder1/folder2/item' If the path itself contains single quote, it should be escaped - add another single quote." — [SwaggerHub PBIRS 2.0](https://api.swaggerhub.com/apis/microsoft-rs/PBIRS/2.0); [Learn: Get Power BI Report](https://learn.microsoft.com/en-us/rest/api/power-bi-report/power-bi-reports/get-power-bi-report)
- Base path and transport: `basePath: /reports/api/v2.0`, host example `localhost`, schemes http/https; the service supports "DELETE, GET, HEAD, PUT, POST, and PATCH methods"; example resource path `CatalogItems(01234567-89ab-cdef-0123-456789abcdef)/Properties`. — [SwaggerHub PBIRS 2.0](https://api.swaggerhub.com/apis/microsoft-rs/PBIRS/2.0); [Learn: Develop with the REST APIs for PBIRS](https://learn.microsoft.com/en-us/power-bi/report-server/rest-api)
- The API "is OData compliant" and Power BI Desktop's OData connector can browse `http://localhost/reports/api/v2.0`, exposing reports, datasets, data sources, and subscriptions; actions like `Model.GetData` are not visible when browsing this way. — [Chris Webb's BI Blog](https://blog.crossjoin.co.uk/2017/10/15/exploring-the-new-ssrs-2017-api-in-power-bi/)
- Error responses use `odata.error` schema (`responses.error -> #/definitions/odata.error`). The spec declares no `securityDefinitions`; authentication is the report server's (Windows/NTLM/Kerberos, or forms cookie via `POST /Session` for custom security). — [SwaggerHub PBIRS 2.0](https://api.swaggerhub.com/apis/microsoft-rs/PBIRS/2.0)

### Inferences
- Because `$expand` is not wired to any operation and sub-resources (DataSources, CacheRefreshPlans, Policies) are separate paths, a connector should expect N+1 calls to enrich a list of reports.
- `$count` being typed `string` in the spec suggests `$count=true` is passed as a literal, OData-style.

### Gaps
- No official documentation of server-side paging defaults (`@odata.nextLink`), maximum `$top`, supported `$filter` operators/functions (e.g., `contains`, `startswith`), or case sensitivity of `$orderBy` vs `$orderby` — the spec only links to the generic OData v4 protocol. Web searches for PBIRS-specific OData quirks returned only unrelated vendors' OData docs.

## Key Question 7 — Differences between SSRS 2017/2019/2022 REST API 2.0 and PBIRS REST API 2.0 regarding PowerBIReports resources

### Takeaway
PBIRS's own spec says it "is a superset of the SQL Server Reporting Services REST API". Programmatic diff of the two SwaggerHub documents: PBIRS has 143 paths vs 111 in SSRS; the 32 PBIRS-only paths are the entire `/PowerBIReports*` tree (16 paths), the entire `/ExcelWorkbooks*` tree (9), `/CacheRefreshPlans({Id})/History`, `/DataSets({Id})/Data`, `/Reports({Id})/Model.UpdateReportDataSets`, and `Model.Upload` on DataSets, DataSources, MobileReports, Reports, Resources; SSRS has zero paths that PBIRS lacks.

### Cited Findings
- PBIRS spec info: "Since Power BI Report Server is a superset of SQL Server Reporting Services, the Power BI Report Server REST API is a superset of the SQL Server Reporting Services REST API." SSRS spec title: "SQL Server 2017 Reporting Services REST API", version 2.0, same `basePath /reports/api/v2.0`. — [SwaggerHub PBIRS 2.0](https://api.swaggerhub.com/apis/microsoft-rs/PBIRS/2.0); [SwaggerHub SSRS 2.0](https://api.swaggerhub.com/apis/microsoft-rs/SSRS/2.0)

Paths only in SSRS: none. — [SwaggerHub PBIRS 2.0](https://api.swaggerhub.com/apis/microsoft-rs/PBIRS/2.0); [SwaggerHub SSRS 2.0](https://api.swaggerhub.com/apis/microsoft-rs/SSRS/2.0)

- Version gating within PBIRS: DataModelRoles/DataModelRoleAssignments require the January 2019 release or later; DataModelParameters require October 2020 or later. — [SwaggerHub PBIRS 2.0](https://api.swaggerhub.com/apis/microsoft-rs/PBIRS/2.0); [Learn: What's new in PBIRS](https://learn.microsoft.com/en-us/power-bi/report-server/whats-new)

### Inferences
- A connector can use the same client for SSRS 2017+ and PBIRS, gating PowerBIReports/ExcelWorkbooks/`CacheRefreshPlans({Id})/History` calls on `GET /System` → `ProductType == "PowerBiReportServer"`.
