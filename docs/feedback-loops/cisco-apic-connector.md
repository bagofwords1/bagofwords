## What was built

- `backend/app/data_sources/clients/cisco_apic_client.py` — `CiscoApicClient`.
  - **Auth:** certificate signatures (RSA PKCS#1 v1.5 / SHA-256 over
    `METHOD + URI + body`, `APIC-Certificate-*` cookies, no session) or a
    password session (`aaaLogin` per operation, `aaaLogout` in `finally`,
    `apic:<domain>\\<user>` for remote users).
  - **Failover:** across up to 5 configured controllers on transport errors
    or a busy cluster.
  - **Single network primitive:** it allows only GET on catalog class paths
    with `query-target-filter` / `order-by` / `page` / `page-size`, plus the
    login and logout POSTs.
  - **Query handling:**
    - JSON queries compile to APIC filter expressions: `eq ne gt ge lt le in`,
      and `contains` as a `wcard` superset re-checked exactly on the returned
      rows.
    - Time windows apply to the table's time column.
    - Node scoping goes through `/api/node/class/topology/pod-<p>/node-<n>/`.
    - Paging uses 500-object pages; `totalCount` above `limit` fails before
      paging.
    - UTC normalisation; the APIC's 1970 "never" becomes null.
    - Derived columns `pod`, `node` and a bracket-aware `parent_dn`.
    - Typed errors that carry the APIC's own reason for 400s.
- `backend/app/data_sources/clients/cisco_apic/catalog.json` — 59 tables, one
  APIC class each. It is generated by `tools/cisco_apic/build_catalog.py` from
  Cisco's model metadata (property names and types, enum values, read access,
  DN formats); `secure` properties are excluded.
- `CiscoApicConfig`, `CiscoApicCertificateCredentials` and
  `CiscoApicPasswordCredentials` in `configs.py`, and `REGISTRY["cisco_apic"]`
  (infra, beta, explicit `client_path`, default auth `certificate`, system
  scope; `userpass` system+user).
- Icon `frontend/public/data_sources_icons/cisco_apic.png`.
- `tools/cisco_apic/simulated_api.py` — a loopback APIC that enforces:
  - login, logout and refresh, idle expiry, and signature verification;
  - the filter grammar (incl. the 20-term cap), `order-by`, paging (2000 cap),
    `totalCount`, `rsp-subtree-include=count` and the error envelope;
  - 503 "dataset too big" on unpaged large classes;
  - refusal of every write (recorded), with subscriptions recorded too;
  - an admin-read RBAC blind spot for a `read-all` account.

  Its fabric holds a planted incident (see `tools/cisco_apic/README.md`).
- Tests:
  - `backend/tests/unit/test_cisco_apic_client.py` (75 tests; most run the
    real client against the simulator over HTTP);
  - `backend/tests/e2e/test_cisco_apic.py` (both auth variants through the
    API);
  - a `cisco_apic` remote-mode entry in `tests/integrations/ds_clients.py`.

### Natural-language agent pass (GPT-6 Luna)

The first try with Claude Haiku 5.5 failed at the provider: the sandbox key had
no credit. The run was repeated with OpenAI GPT-6 Luna as the org default.

Steps: connect through the UI with certificate auth, select 59/59 tables,
create the agent, then send this prompt:

> Since about 40 minutes ago the checkout app servers (EPG app, tenant retail)
> can't reach their PostgreSQL database (EPG db). Investigate the ACI fabric:
> check faults, events and the audit log for the last 2 hours, where the db
> servers are attached, and the policy and paths between app and db. Tell me
> the most likely root cause with evidence, and list other problems you find
> that are not the cause.

**Result (about 7 minutes, 3 sub-agents)**

**Most likely root cause: PostgreSQL filter port changed.** The audit log
records `netops-jlee` changing both destination-port bounds on
`uni/tn-retail/flt-postgres/e-pg-5432` from postgresql to 5433, about 13
minutes before the reported outage. A targeted query confirmed the filter
entry now matches 5433 only.

Luna also reported:
- the db endpoints 10.10.30.21–23 attach on db-vpc, leaf pair 303–304;
- the app-to-db contract links are intact;
- the BGP peer 10.200.0.5 flap on node 304 is a separate issue, not the cause;
- the EPG db health fault and the zoning update are consequences of the
  change;
- the `corp-wan` description edit is unrelated.

It **missed the leaf 303 uplink optic failure**. It said itself that a broad
events query and a link-health review did not complete.

**What the run's tool log exposed (fixed in `3875b098`, each with a regression test)**

1. Filters on `parent_dn`, `node` and `pod` were rejected, although the schema
   lists them. They are now filterable: a superset `wcard` on `dn` at the
   APIC, then an exact check on the returned rows.
2. Wrong property guesses (`tenantId`, `adminSt`, `state`, `tDn`) got
   "use get_schema", which the code sandbox does not offer. The error now
   names close matches and the table's main properties.
3. The model passed small `limit` values as a preview size and hit
   `ResultLimitExceeded` eight times. That is how the uplink evidence was lost.
   The ceiling semantics stay (never truncate), but the error now says
   "limit is N … drop limit and use .head(n)", and the description says so up
   front.
4. The simulator rejected `baseEpgDn`, a real `fvCEp` property it had not
   seeded. It now accepts every model property of a class, as an APIC does.

Platform-side, not connector logic:
- the model guessed `ds_clients` keys (`'ACI Fabric'`, `'ACI Fabric:DC1'`);
- sub-agent `read_sub_agent` repeats.

**Not yet observed:** a second Luna run on the fixed build. A sandbox
restart regenerates `BOW_ENCRYPTION_KEY` and invalidates stored
credentials; set a stable key before rerunning.

## Faithfulness limits (see `tools/cisco_apic/SOURCES.md`)

These are verified from Cisco docs, Cisco's model metadata and maintained
clients (Cobra, Ansible `cisco.aci`, DataDog): the login, signature, filter,
paging and error shapes, plus the class and property names.

These are inferred and need a real fabric:
- that admin-only classes return empty rather than 403 for `read-all`;
- the epoch-as-never convention;
- `wcard` regex semantics;
- the throttling status codes.

Before GA, run a read-only pass on a 6.x fabric with a `read-all` user, and
with admin read.
