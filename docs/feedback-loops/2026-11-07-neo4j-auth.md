# Feedback Loop — Neo4j connector: enterprise auth, admin limits, graph algorithms

The Neo4j connector only offered username / password. Enterprise customers
also sign in with SSO tokens, Kerberos (often per user), or a service account
that acts as each user. This change adds those options, plus three settings an
admin can change per connection (row limit, schema sample size, graph
algorithms). The claim validated here: each option connects, indexes the
catalog and answers questions through the real app, and Neo4j enforces the
right user's permissions.

## What changed

| Option | Where | Scope |
|---|---|---|
| Username / password (also LDAP, which the server checks) | existing | system, user |
| SSO access token (OIDC): `bearer_auth(token)` | `Neo4jBearerCredentials` | system, user |
| Impersonation: a service user plus `impersonated_user` on every session | `Neo4jImpersonationCredentials` | system; under "Require user authentication" the field is bound to a member attribute (`member_mapped`), never typed by members |
| Kerberos: BOW's own identity (keytab / default cache) | `Neo4jKerberosCredentials` | system |
| Kerberos SSO via constrained delegation, as for SQL Server | `Neo4jKerberosDelegatedCredentials` | user (default when system auth is Kerberos) |
| No authentication | `Neo4jNoAuthCredentials` | system |
| Row limit, schema sample size, allow GDS, Kerberos service name | `Neo4jConfig` | connection settings |

Code:
- `backend/app/data_sources/clients/neo4j_client.py`: `_auth()` picks the
  driver auth. Kerberos goes through an `AuthManager` that mints a GSS-API
  token from the ticket manager's credential cache (`kerberos_token`), renews
  it before it expires, and replaces it once when the server rejects it.
  Delegation without a verified directory SID is refused, as in
  `mssql_client.py`. `connect()` passes `impersonated_user` to every session.
- `backend/app/data_sources/clients/cypher_guard.py`: `check_cypher(..., allow_gds=)`
  adds GDS stream / stats / estimate modes, projection (`gds.graph.project`,
  procedure and aggregation function), `gds.graph.drop/list/exists`,
  `gds.list`, `gds.util.asNode(s)`. Write / mutate modes, exports, and
  Cypher-string projections stay refused.
- `backend/app/ai/code_execution/sql_guard.py`: the executor's own read-only
  check now passes the connection's `allow_gds` (found by Loop B, see below).
- `backend/app/services/connection_service.py:363`: Kerberos system auth
  defaults members to `kerberos_delegated` for `neo4j` as for `MSSQL`.
  `user_data_source_credentials_service.py` fills Kerberos schema defaults for
  `neo4j` as for `mssql`. The rest of Kerberos SSO (directory identity checks,
  ticket manager, member roster) was already type-agnostic.

### Found by this loop and fixed

- With "Allow graph algorithms" on, the agent's first GDS call failed with
  `Security violation (unsafe_sql): CALL gds.graph.drop is not allowed`, and
  Haiku fell back to hand-written PageRank in Cypher. Cause: the code
  executor checks Cypher a second time in `sql_guard.ensure_read_only`, which
  called `check_cypher(query)` without the connection's setting. Fixed to pass
  `client.allow_gds`; regression test added; re-run shown above.
- The label "Service user + impersonation" was cut off in the auth menu;
  renamed "Impersonation".

## Not verified live (and why)

- **SSO token accepted by Neo4j**: needs Neo4j Enterprise with OIDC set up
  against an identity provider. Verified: the driver sends the bearer
  scheme with the token, and the server's refusal never shows the token.
- **Kerberos**: needs a KDC, Active Directory delegation and Neo4j's Kerberos
  add-on. Unit tests cover the token target, credential cache choice, renewal
  and the SID check. Delegation itself reuses the SQL Server path, which was
  proven in a Samba AD lab (see `tests/e2e/test_kerberos_sso_member_overlay.py`).
  Production deployments need `gssapi` + MIT krb5 on the BOW server, as for
  SQL Server Kerberos.

## Notes (not caused by this change)

- The row-limit notice reaches the code's run log, but Haiku still said
  "none truncated". How much of the run log the planner weighs is a pipeline
  question and applies to every connector that sets `bow_notice`.
- Haiku's `describe_tables` sometimes got nothing back for `Person` before it
  retried with `(:Person)`; the catalog names keep the Cypher syntax.
- The dev backend hung once after an auto-reload (a stuck code-sandbox child
  kept the old process alive); `boot_stack.sh --stop` did not kill it. Killing
  the processes and booting again fixed it.
