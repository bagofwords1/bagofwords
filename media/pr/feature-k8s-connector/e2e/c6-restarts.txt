The rest range from 1–9 restarts, spread across bow-test, envoy-gateway-system, metallb-system, and container-registry. Despite the restart counts, every pod is currently Running and ready — the pattern (many system pods restarting around the same startup window on Sept 1) suggests node reboots/restarts rather than individual crash loops.

Recent Warning events — 16 events, all from today ~10:33–10:36 UTC

Three distinct problem clusters:

Image pull failures (bow-test) — the most active issue:

mysql-778b6d9479-8lgbf can’t pull mysql:8.4-0asdsd — image tag not found (looks like a typo’d tag), now in ImagePullBackOff.

bow-runtime-data-edge-agent-845f7fc65d-9xdpv can’t pull localhost:32000/bagofwords:dev-mcp-1 — image not found in the local registry, also ImagePullBackOff.

Readiness/liveness probe failures — envoy-gateway, two envoy proxy pods, openshell-0, and calico-kube-controllers all failed probes with timeouts or connection refused in the same ~1-minute window. Combined with the crash back-off events below, this looks like a brief cluster-wide disruption (likely the node coming back up) rather than per-service issues.

Crash back-offs — hostpath-provisioner and agent-sandbox-controller each hit “Back-off restarting failed container” once, consistent with their high restart counts.

Bottom line: the two ImagePullBackOff pods in bow-test are the real actionable problems — one bad image tag (mysql:8.4-0asdsd) and one missing image in the local registry (bagofwords:dev-mcp-1). Everything else appears to be transient fallout from a node/cluster restart and has since recovered.
